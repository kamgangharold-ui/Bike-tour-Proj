# FlutterFlow Setup Guide — State Management & Conditional UI

## 1. App State Variables

In FlutterFlow → **App State → Add Fields**. All are persisted in memory (not to device storage).

| Variable | Type | Initial value | Purpose |
|---|---|---|---|
| `activeLocationSlug` | String | `""` | Slug of current geofenced landmark; empty = no active landmark |
| `activeLocationName` | String | `""` | Display name |
| `activeLocationDescription` | String | `""` | Short description (notification body) |
| `activeLocationCategory` | String | `""` | `landmark / dismount_zone / parking / hazard / viewpoint` |
| `activeLocationIsRegulatory` | Boolean | `false` | Drives full-screen alert rendering |
| `activeLocationRegulatoryMessage` | String | `""` | Regulatory warning text |
| `activeLocationRegulatoryFineEur` | Double | `0` | Fine in EUR (0 = no fine) |
| `activeLocationAffiliateUrl` | String | `""` | GetYourGuide deep-link |
| `activeLocationAudioUrl` | String | `""` | Firebase Storage audio URL |
| `isSubscribed` | Boolean | `false` | `true` when `users.subscription_status == "active"` |

## 2. Register the Geofence State Callback

In FlutterFlow → **Custom Code → Add Custom File** → paste the snippet below as
`app_geofencing_init.dart`. This file wires `GeofencingActions.onLandmarkEntered`
(from `start_geofencing.dart`) to `FFAppState`.

```dart
// app_geofencing_init.dart
// Call registerGeofencingCallback() from your app's MyApp.initState
// AFTER calling initializeRadar() and startGeofencing().

import 'package:your_app/flutter_flow/flutter_flow_util.dart'; // auto-generated by FF
import 'start_geofencing.dart';

void registerGeofencingCallback() {
  GeofencingActions.onLandmarkEntered = ({
    required String slug,
    required String name,
    required String description,
    required String category,
    required bool isRegulatory,
    required String regulatoryMessage,
    required double regulatoryFineEur,
    required String affiliateUrl,
    required String audioUrl,
  }) {
    FFAppState().update(() {
      FFAppState().activeLocationSlug = slug;
      FFAppState().activeLocationName = name;
      FFAppState().activeLocationDescription = description;
      FFAppState().activeLocationCategory = category;
      FFAppState().activeLocationIsRegulatory = isRegulatory;
      FFAppState().activeLocationRegulatoryMessage = regulatoryMessage;
      FFAppState().activeLocationRegulatoryFineEur = regulatoryFineEur;
      FFAppState().activeLocationAffiliateUrl = affiliateUrl;
      FFAppState().activeLocationAudioUrl = audioUrl;
    });
  };
}
```

Call order in `MyApp.initState`:
```
initializeRadar()  →  startGeofencing()  →  registerGeofencingCallback()
```

## 3. Page Architecture

```
MapPage (root, always visible)
├── GoogleMap or custom map widget
└── LandmarkBottomSheet (conditional: activeLocationSlug != "")
    ├── LandmarkCard widget  ← custom widget from landmark_card.dart
    └── [dismiss] sets activeLocationSlug = ""
```

Implement the bottom sheet as a **Stack** on the map page with a **Conditional** widget:
- **Condition:** `FFAppState().activeLocationSlug != ""`
- **True branch:** `DraggableScrollableSheet` containing `LandmarkCard`
- **False branch:** nothing (empty Container)

## 5. Visited Badge — `isVisited` Binding

`users.visited_location_slugs` is an `Array<String>`. The `isVisited` parameter should be:

```
currentUserDocument.visitedLocationSlugs
    .contains(FFAppState().activeLocationSlug)
```

In FF, use the **List → Contains Item** condition operator on the Firestore document stream.

**On geofence entry — first visit:** add a native FF Firestore action to append the slug:

```
Action: Update Document
Collection: users
Document: currentUserDocument
Field: visited_location_slugs → [Union Array] activeLocationSlug
```

## 6. Quiz — Firestore Query & Completion Gate

**Firestore query** to bind quiz data (add as a Backend Query on the bottom sheet or LandmarkCard parent):

```
Collection: quizzes
Filter:  location_slug == FFAppState().activeLocationSlug
         is_active     == true
Limit:   1
```

From the result document, map fields to widget parameters directly.

**`quizAlreadyCompleted` binding:**
```
currentUserDocument.completedQuizIds.contains(quizDocumentId)
```

**On correct answer — record completion:**
```
Action 1: Update Document
  Collection: users / currentUserDocument
  Field: completed_quiz_ids → [Union Array] quizDocumentId

Action 2: Cloud Function call → incrementUserPoints(uid, points)
```
> Points **must** be incremented server-side (Cloud Function) to prevent client-side manipulation. Client writes to `total_points` are blocked by Firestore Security Rules.

## 7. FAQs — Firestore Query

**Firestore query** (add alongside the quiz query):

```
Collection: faqs
Filter:  location_slug == FFAppState().activeLocationSlug
         is_active     == true
Order:   sort_order ASC
Limit:   10
```

Map the result to three parallel lists:
- `faqQuestions` ← `question` field
- `faqAnswers` ← `answer` field
- `faqIsPremium` ← `is_premium` field

## 8. Subscription Status — `isSubscribed` Sync

On app launch and after any Stripe payment, update `FFAppState().isSubscribed`:

```
Action: Update App State
  isSubscribed = (currentUserDocument.subscriptionStatus == "active")
```

Wire this action to:
- **MyApp initState** (after user document loads)
- **Stripe payment success webhook redirect** page

## 9. Conditional UI Rules Summary

| Component | Visible when |
|---|---|
| `LandmarkBottomSheet` | `activeLocationSlug != ""` |
| Regulatory banner inside card | `activeLocationIsRegulatory == true` |
| Audio guide button | `activeLocationAudioUrl != ""` |
| Book a Tour button | `activeLocationAffiliateUrl != ""` |
| Quiz section | `quizQuestion != "" && !quizAlreadyCompleted` |
| FAQ section | `faqQuestions.length > 0` |
| FAQ premium lock icon | `faqIsPremium[i] == true && isSubscribed == false` |
| Visited badge on card | `isVisited == true` |
